# Next.js best practices

Source: nextjs.org/docs (App Router, v16). Apply these when touching `src/app/**`.

## Project structure
- Routing files (`page`, `layout`, `loading`, `error`, `not-found`, `route`) go in `src/app`; a folder is only a public route once it has a `page` or `route` file — everything else can be colocated safely.
- Use `_folder` (underscore prefix) for non-routable helpers colocated inside a route segment (e.g. `_components`, `_lib`).
- Use `(group)` route groups to share a layout across routes without affecting the URL, or to give a route subset its own layout.
- Prefer the `src/` layout (already in use here) to keep app code separate from root config files.

## Images
- Always use `next/image`, never a raw `<img>`.
- Prefer static `import` of local images so width/height/blurDataURL are inferred automatically (prevents CLS) — only pass explicit `width`/`height` when the src is a string path or remote URL.
- Set `priority` only on the above-the-fold / LCP image; everything else lazy-loads by default.
- For remote images, declare `images.remotePatterns` in `next.config.ts` as narrowly as possible (protocol + hostname + pathname) — never allow `**` on an untrusted host.

## Fonts
- Use `next/font/google` or `next/font/local`, never a `<link>` to Google Fonts or `@import` in CSS — this self-hosts fonts and removes layout shift plus the external network request.
- Prefer variable fonts (no `weight` needed); set a `variable` CSS custom property and apply it via `className` on `<html>`/`<body>`, not inline styles.

## Metadata
- Export a static `Metadata` object from `layout.tsx`/`page.tsx` for fixed metadata; use `generateMetadata()` only when metadata depends on fetched/dynamic data.
- Set `metadataBase` in the root layout so relative OG/Twitter image URLs resolve correctly.
- Give the root layout a real `title`/`description` — never ship the `create-next-app` placeholder ("Create Next App" / "Generated by create next app") to production.
- If the same data is needed in both `generateMetadata` and the page body, wrap the fetcher in React's `cache()` to dedupe the request.

## When improving this project
1. Check whether a change duplicates an existing colocated helper before adding a new one.
2. Keep the `src/app` root layout as the single source of global metadata/fonts; don't redeclare fonts per-route.
3. Run `pnpm lint` and `pnpm build` after any change to `src/app/**`.
